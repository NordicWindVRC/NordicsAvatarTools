# Nordic's Submesh Splitter

Many avatar bodies and outfits are one mesh made of several parts, one per material: for
example the body, the head, the hair and the nails. Normally you can only edit that mesh as a
whole. The Submesh Splitter splits it into separate objects, one per material, so you can
work on each part on its own:

- **Hide a part completely** by turning its object off. No extra tool needed.
- **Reduce the polygons** of one part more than another, with a mesh simplifier such as Meshia.
- **Cut away pieces** of one part with Modular Avatar's Mesh Cutter.
- **Add an on/off toggle** for one part with Nordic's Blendshape Toggle.

When you build or upload the avatar, the parts are joined back into the original mesh
automatically, with your changes applied. Your original model, prefab and scene are never
changed.

## Before you start

- You need a VRChat avatar project with **NDMF**. If you already use Modular Avatar or VRCFury,
  you have it.
- Make a backup or commit your project first, as with any new tool.
- The mesh must have **Read/Write** enabled. If it doesn't, the component tells you. Select
  the model file, and in the Inspector's **Model** tab tick **Read/Write**, then click **Apply**.

## Quick start

1. Open your avatar prefab by double-clicking it in the Project window. You can also use an
   avatar object in a scene, as long as it isn't a prefab.
2. Select the object that has the mesh you want to split, for example **Body**. It has a
   **Skinned Mesh Renderer** component.
3. In the Inspector, click **Add Component** and choose **NordicWind → Nordic's Submesh Splitter**.
4. Click **Update split meshes**.

A new child object, `Nordic_SplitMeshes`, appears, with one object per part. Each is named
after its material, for example `Submesh_2_Hair`. The original mesh is hidden while you edit;
the parts are what you see in the editor. Build or enter Play Mode as usual, and the avatar
looks the same as before, but now each part can be changed on its own.

## Common tasks

| I want to… | Do this |
|---|---|
| Remove a part from the avatar | Select its object under `Nordic_SplitMeshes` and untick it (top of the Inspector). It is left out of the build. You don't need a Mesh Cutter for this. |
| Simplify one part | Add your simplifier (for example **Meshia Mesh Simplifier**) to that part's object and choose its settings. |
| Cut away part of a part | Add **MA Mesh Cutter** to that part, or point an existing one at it. |
| Toggle a part in-game | Add **Nordic's Blendshape Toggle** to the **original** object (for example Body), choose the part's material slot, and animate it on the original object. |
| Change materials | Change them on the **original** renderer as usual. The parts follow when you click **Update split meshes**, and the build always uses the original's materials. |
| Use AAO, VRCFury or other general tools | Put them on the **original** object or the avatar as usual, never on the split parts. |
| Update after changing the model | Click **Update split meshes** again. Your settings on the parts are kept. Parts are added or removed if the number of materials changed. |
| Clean up old generated files | **Tools → NordicWind → Submesh Splitter → Clean Up Unused Split Mesh Assets**. It lists unused files and moves them to the recycle bin only after you confirm. |

Generated meshes are stored in `Assets/NordicWind/Generated/SubmeshSplitter/`.

## Troubleshooting

| Message | What it means and what to do |
|---|---|
| *This renderer belongs to a prefab…* with an **Open Prefab** button | The object is part of a prefab placed in a scene. Click **Open Prefab** and update the split there, so every copy of the prefab stays the same. |
| *Save the scene before generating* | The split files belong to the scene, so it needs to be saved first. |
| *The split was generated by an older version* or *The source mesh changed…* | The model changed since you split it. Click **Update split meshes**. Builds stop until you do, so you never upload an outdated mesh. |
| *…vertices are shared between submeshes…* (warning) | Parts touch at their edges. That's fine, but if you simplify neighbouring parts differently, small gaps can appear along those edges. |
| Build stops: *Another tool changed the original mesh…* | A mesh-editing tool was put on the original object. Move it to the part it should affect. |
| Build stops: *…has not been applied and would be lost* | A component on a split part never ran, for example an AAO or VRCFury component. Move it to the original object. |
| Build stops: *Animation targets a split part* | An animation turns a split object on or off. Split objects don't exist after the build, so animate the original object instead, or use Nordic's Blendshape Toggle. |

When the Splitter stops a build, a dialog explains why. In Play Mode, Play Mode is stopped too.

## Works with

| Tool | How |
|---|---|
| Modular Avatar | Mesh Cutter works on split parts, including toggled cuts. Other MA components go on the original. |
| Meshia | Simplify each part with its own settings. |
| Avatar Optimizer (AAO) | Runs after the parts are joined, on the original. Put AAO components on the original. |
| VRCFury | Works with the original as usual, including Blendshape Optimizer, toggles, face tracking and Armature Link. VRCFury never sees the split parts. |
| Nordic's Blendshape Toggle | Add it to the original and pick a material slot. It acts on that part. |

None of these are required.

## Limitations

- A prefab placed in a scene must be split in the prefab itself.
- Animations that turn split objects on or off don't work, because those objects don't
  exist after the build. Animate the original object instead.
- If a tool removes everything from a part, the build stops. Turn the part off instead.
- Some uncommon mesh data is not kept: vertex data beyond UV0–UV7, and compressed vertex
  formats, which are stored as full-precision floats.

## Technical details

<details>
<summary>How the Splitter works during a build</summary>

**In the editor**, the source mesh is copied once per material slot, and each copy keeps only
that slot's triangles. All vertex data, skinning and blendshapes are kept. A fingerprint of the
source mesh is stored with the split, covering geometry, skinning, blendshapes and layout. It
doesn't depend on which scene or prefab the mesh is in, so outdated splits are detected
everywhere. A prefab variant that updates an inherited split gets its own files and never
changes the base prefab's files.

**During a build:**
1. *NDMF Resolving:* every split is checked against its fingerprint. The original renderer's
   mesh, blendshapes and weights are recorded.
2. *Per-part actions run:* Blendshape Toggle placeholders (Generating), MA (Transforming).
3. *VRChat SDK builds and VRCFury Play Mode:* while non-NDMF tools such as VRCFury run (SDK
   callbacks −10500 to −1030), the parts are moved out of the avatar, then put back in place.
   Bone changes those tools made to the original renderer, such as Armature Link, are copied
   to the parts.
4. *NDMF Optimizing, after Meshia and before AAO:* the enabled parts are joined into a new
   mesh on the original renderer:
   - Materials, bounds and the enabled state come from the original.
   - The blendshape list follows the original's current list and order, so eyelid settings
     stay valid.
   - Shapes another tool renamed (VRCFury face tracking) keep their data under the new name.
   - Shapes another tool removed (VRCFury Blendshape Optimizer) are baked in at their weight.
   - Only vertices that are actually used are kept. The original bone order is reused.
5. The split objects and the component are removed. The original renderer and its object
   are kept, so existing animations and descriptor settings still work.

</details>
